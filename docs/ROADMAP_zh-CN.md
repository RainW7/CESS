# CESS 后续路线图

[English](ROADMAP.md) | [简体中文](ROADMAP_zh-CN.md)

CESS v0.9.0聚焦快速一维无缝光谱。以下为未来工作计划，不是本版本已经交付的能力，也没有承诺固定发布时间。

## 一维版本维护

- 保持BayeSED输入和版本化产品的可读性，修复问题时记录科学定义与迁移影响。
- 按实际平台核查依赖和资源来源，测量不同样本、worker数与内存下的性能。
- 针对科研用途补充PSF/LSF、背景、孔径与灵敏度定标，以及发射线完备度和污染评估。

## CESS+：从单源二维到CCD场景

1. **接口与电子预算**：明确SED、图像坐标/WCS、PSF/LSF、谱级响应、像元、曝光和噪声的单位与应用位置，以静态点源和窄线算例检查通量守恒。
2. **单源零级/一级图像**：选择输入源与观测参数，输出各谱级的无噪期望、含噪二维图像、方差/掩膜、trace/波长映射及对应的一维数据。
3. **真实天区的单CCD场景**：按星表位置和WCS投影源，先叠加所有源的期望，再加入探测器噪声；记录边界损失、谱级和来源。
4. **场景提取与污染处理**：利用直接像/星表先验、trace和响应提取各源光谱，输出误差、污染模型及质量标记，以孤立源、重叠源和边缘源分别验收。
5. **延展盘星系运动学**：建立源平面的Doppler前向模型，先验证静态控制，再开展多PA、S/N、尺寸和速度参数的注入回收，报告偏差、退化与选择效应。

二维依赖保持可选，一维运行不应被迫先生成二维图像。原始数据、truth和观测噪声产品分别保存，不能把已经含噪的一维谱当作无噪输入再次叠加噪声。历史二维原型的存在不代表已获得可用的CCD/WCS或运动学恢复能力。

已有原型和外部后端的接口、单位、许可证与Python3.12兼容性需分别审查；不会将它们未经核验整体搬入当前一维核心。未来具体方案以相应版本的设计与验收文档为准。
